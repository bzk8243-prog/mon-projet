# Lonage Execution System

## Purpose
Provide a practical, full-site implementation system for Lonage based on the SEO audit and ecosystem inventory.

This system covers all ecosystems: Menopause, Healthy Aging, Fitness After 50, Nutrition, Sleep, Mobility, Recovery, Gut Health, Longevity, Women’s Wellness.

It preserves all existing URLs and WordPress categories, and it is designed for the current Lonage architecture.

## 4. Workflows

### 4.1 Daily workflow
1. Review the editorial queue for today’s article or update.
2. Confirm ecosystem, pillar, and cluster assignments.
3. Draft or revise content using the approved templates.
4. Add required internal links: pillar, sibling, cross-ecosystem.
5. Run Rank Math optimization and checklist.
6. Submit for human review or publish if complete.
7. Log the work in `published-articles.md` or `content-update-log.md`.

### 4.2 Weekly workflow
1. Monday: topic selection and cannibalization review.
2. Tuesday: outline, brief, SEO intent, and link target planning.
3. Wednesday: write draft content.
4. Thursday: edit, optimize, and add internal links.
5. Friday: publish, QA, and submit indexing request.
6. Weekly review: update editorial queue and track in `content-calendar.md`.

### 4.3 Monthly SEO maintenance workflow
1. Crawl all published URLs.
2. Identify orphan and weakly linked pages.
3. Refresh internal links on at-risk pages.
4. Re-check Rank Math structure on priority posts.
5. Audit pillar-cluster coverage by ecosystem.
6. Update the global authority map and editorial queue.
7. Plan next month’s ecosystem focus.

### 4.4 Article publishing workflow
1. Confirm article fits one primary ecosystem.
2. Assign primary cluster and parent pillar.
3. Validate no existing URL or slug changes.
4. Write the article according to the ecosystem template.
5. Add at least 4 internal links before publishing.
6. Run Rank Math optimization.
7. Complete WordPress publishing checklist.
8. Publish and add to the performance tracker.

### 4.5 Internal linking workflow
1. Read the latest inventory and authority map.
2. Identify pillar pages and cluster siblings for the article.
3. Add a parent pillar link in the top section.
4. Add 2-3 sibling links in the body.
5. Add 1-2 cross-ecosystem links when relevant.
6. Verify anchor text matches search intent.
7. Log the link changes and QA the final page.

### 4.6 Content refresh workflow
1. Identify candidate pages from performance or age.
2. Review current intent, rankings, and Rank Math suggestions.
3. Update content for accuracy, examples, and UX.
4. Add fresh internal links to pillar and sibling content.
5. Re-optimize titles, meta descriptions, and headings.
6. Publish the refresh and record the date.
7. Monitor performance for 4 weeks.

### 4.7 Orphan article recovery workflow
1. List orphan articles from the audit.
2. Assign each orphan to a primary pillar.
3. Add a direct link from the assigned pillar page.
4. Add 2 sibling cluster links.
5. Add 1 cross-ecosystem contextual link if appropriate.
6. Mark the orphan as recovered in the tracker.
7. Re-run the orphan audit next month.

### 4.8 Pillar expansion workflow
1. Review pillar pages and cluster inventory.
2. Identify missing clusters and low-depth areas.
3. Add summary sections for each cluster to the pillar.
4. Add links to existing and planned cluster articles.
5. Schedule content creation for missing cluster pages.
6. Refresh pillar content quarterly as ecosystems grow.

## 5. Publishing Cadence
- Realistic target: **1-2 published pages per week** while foundations are built.
- Aim for **1 new pillar page per month** for empty ecosystems.
- After foundations: **2-4 new cluster articles per month per ecosystem**.
- Long-term cadence: **4-6 published pages per month across all ecosystems**.
- Maintain a balanced mix: 30% pillar updates, 50% cluster pages, 20% optimization/refresh.

---

## 6. Article-to-Cluster Rules
1. Every article must map to one primary cluster.
2. Title and keyword intent must match the cluster concept.
3. Only one article should own each distinct keyword target within an ecosystem.
4. If similar intent exists, merge or redirect rather than publish duplicates.
5. Cluster articles should answer a focused user question inside the cluster theme.
6. Each article must link back to the parent pillar and to 2 sibling cluster articles.

---

## 7. Cluster-to-Pillar Rules
1. Each cluster belongs to one primary pillar.
2. Pillars should summarize cluster themes and link to all cluster articles.
3. Pillar pages should be the top-level hub for the ecosystem.
4. Pillars should include at least one cross-ecosystem bridge section.
5. Cluster articles should include a pillar link in the top third of content.
6. Pillars should receive links from cluster articles when appropriate.

---

## 8. Cross-Ecosystem Linking Rules
1. Use cross-ecosystem links only when the topic is genuinely relevant.
2. Limit cross-ecosystem links to 1-2 per article.
3. Prefer established pillar or strong cluster pages as cross-ecosystem targets.
4. Use the global authority map to identify natural bridges.
5. Do not create cross-links solely for backlink volume.
6. Ensure cross-links preserve user flow and topical relevance.

### Recommended cross-ecosystem bridges
- Menopause ⇄ Sleep
- Menopause ⇄ Nutrition
- Menopause ⇄ Recovery
- Nutrition ⇄ Gut Health
- Nutrition ⇄ Fitness
- Sleep ⇄ Longevity
- Fitness ⇄ Recovery
- Fitness ⇄ Mobility
- Healthy Aging ⇄ Longevity
- Women’s Wellness ⇄ Menopause

## 9. Rank Math Optimization Checklist
1. Primary keyword set and aligned with the target article.
2. SEO title optimized for clarity and click intent.
3. Meta description written for benefit and relevance.
4. H1 is unique and keyword-aligned.
5. H2/H3 structure supports subtopics and readability.
6. Focus keyword appears naturally in the first 100 words.
7. Internal links present: pillar, sibling, cross-ecosystem.
8. Image alt text optimized and descriptive.
9. Content length matches topic intent and competitor benchmarks.
10. Schema types applied if appropriate.
11. Readability score reviewed and improved.
12. No URL changes; existing slugs preserved.
13. No keyword stuffing or irrelevant repeated phrases.

---

## 10. WordPress Publishing Checklist
1. Confirm correct category assignment.
2. Preserve existing URL slugs for published or updated pages.
3. Set the parent pillar and cluster tags if used.
4. Add featured image and image alt text.
5. Set publication status correctly (Draft, Pending Review, Published).
6. Add excerpt/summary if used by the theme.
7. Verify internal links in the editor and preview.
8. Check Rank Math settings and preview snippet.
9. Add or update canonical tags only if needed and preserve current URL.
10. Schedule or publish immediately based on editorial plan.
11. Record publication/update date in the tracking spreadsheet.
12. Submit the page for indexing if it is new or significantly updated.

---

## 11. Implementation Notes
- Preserve all existing URLs and categories.
- Use current WordPress structure and slug rules.
- Avoid wholesale reorganizing taxonomy at this stage.
- Focus first on publishing pillars and cluster content, then on scaling.
- Keep the Lonage content architecture as the guiding framework.
- Execute with a mix of immediate repairs and sustainable growth.

This Lonage execution system gives the team a clear roadmap, exact order of operations, and repeatable workflows for daily, weekly, and monthly execution across all ecosystems.
