# Lonage SEO Authority System: WordPress Implementation Roadmap

## Purpose
This roadmap explains how to apply the Lonage SEO authority architecture on the live WordPress site while preserving indexed URLs, categories, and slugs.

## Implementation Principles
- Preserve all indexed URLs and categories.
- Do not rename existing slugs.
- Improve authority through structure, linking, and editorial operations.
- Use Rank Math as a quality framework, not as a keyword-stuffing target.

---

## Phase 1 — Baseline & Setup (Week 1)

1. **Inventory current content**
   - Export all published URLs, categories, tags, and post dates.
   - Capture current pillar candidates and existing cluster posts.

2. **Authority mapping**
   - Map every post to one ecosystem and one parent pillar.
   - Flag posts with unclear pillar fit for editorial review.

3. **Rank Math baseline configuration**
   - Confirm site-level metadata templates.
   - Set preferred schema defaults per post type.
   - Validate XML sitemap coverage for posts/pages/categories.
   - Ensure breadcrumbs are enabled if used by theme.

4. **Operational trackers**
   - Use linking tracker for A–F menopause clusters and global ecosystems.
   - Create status board: To Audit / To Update / QA / Published.

---

## Phase 2 — Category Strategy Implementation (Week 2)

1. Keep existing categories unchanged.
2. Map each category to one of the 10 ecosystems:
   - Menopause, Healthy Aging, Fitness, Women’s Wellness, Recovery,
     Nutrition, Sleep, Gut Health, Mobility, Longevity.
3. Define category role:
   - Core ecosystem category,
   - Supporting subcategory,
   - Utility/archive category.
4. Add category-level editorial notes:
   - primary intents,
   - preferred pillar pages,
   - cross-category bridge priorities.

---

## Phase 3 — Pillar Page Implementation (Weeks 2–3)

1. Confirm existing pillar pages per ecosystem.
2. For missing pillars, publish new pillar pages without modifying existing URL structures.
3. On each pillar page:
   - add clear intro intent statement,
   - add structured links to all assigned cluster pages,
   - add “related ecosystem” bridges.
4. On each cluster page:
   - include at least one contextual link to its parent pillar in upper content.

---

## Phase 4 — Internal Linking Implementation (Weeks 3–4)

1. Apply global linking quotas:
   - Pillars: 8–20 internal links.
   - Cluster pages: 3–7 links (pillar + siblings + bridge).
2. Add sibling links inside each cluster group.
3. Add cross-ecosystem links based on user journey relevance.
4. Keep anchors natural, varied, and intent-matched.
5. Re-crawl and verify link graph improvements.

---

## Phase 5 — Orphan Article Recovery (Week 4)

1. Detect orphans (0 contextual inlinks).
2. Assign each orphan to ecosystem + parent pillar.
3. Recover with:
   - 1 pillar inlink,
   - 2 sibling inlinks,
   - 1 cross-ecosystem contextual inlink.
4. Add reciprocal link from orphan to parent pillar.
5. Re-crawl and mark resolved.

---

## Phase 6 — Publishing Workflow (Ongoing)

1. **Briefing**
   - assign ecosystem + pillar + target cluster.
2. **Drafting**
   - write to intent and editorial tone.
3. **SEO pass (Rank Math)**
   - focus keyword, title/meta, schema, heading hierarchy.
4. **Linking pass**
   - pillar link + sibling links + cross-ecosystem bridge.
5. **Editorial QA**
   - human style, clarity, and medical framing checks.
6. **WordPress publish/update**
   - publish without slug/category changes unless absolutely required.
7. **Post-publish tracking**
   - monitor impressions, CTR, positions, and inlink growth.

---

## Phase 7 — Editorial SOPs (Ongoing)

Editors should follow SOP gates for every update/new post:
- Ecosystem and pillar assignment confirmed.
- Internal linking quota met.
- Rank Math issues reviewed and addressed.
- Content remains human-sounding and brand-consistent.
- Update logged in maintenance tracker.

---

## Future Article Integration Model

Every future post must enter the authority structure through this sequence:
1. assign ecosystem,
2. assign parent pillar,
3. assign sibling cluster group,
4. define at least one cross-ecosystem bridge,
5. publish with required internal links,
6. schedule 30/90-day audit checkpoints.

---

## SEO Maintenance Workflow (Monthly)

1. Crawl site and refresh inlink/orphan report.
2. Review pillar health and cluster coverage gaps.
3. Update decaying pages before creating net-new content.
4. Improve internal links on underperforming posts.
5. Revalidate Rank Math structure on top-priority URLs.
6. Update authority map with new posts and bridges.

---

## Future Scaling Strategy (Quarterly)

1. Expand each ecosystem with missing authority pages.
2. Strengthen cross-ecosystem bridges where user journeys overlap.
3. Consolidate thin overlapping posts into stronger hubs (without URL changes unless migration is planned carefully).
4. Build advanced cluster depth in high-performing categories first.
5. Maintain a rolling editorial calendar tied to ecosystem gaps and performance data.
